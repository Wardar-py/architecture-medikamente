# Проектирование решения (To-Be, Privacy by Design)

## 1. Подход

Решение спроектировано по принципу **Privacy by Design** (privacy by default):
конфиденциальность встроена в архитектуру, а не добавляется постфактум.
Новые интеграции не требуют повторной валидации, потому что защита данных
реализована на инфраструктурных блоках, через которые проходят все потоки.

## 2. Новые блоки в архитектуре

| Блок                                            | Роль в защите конфиденциальности                                                                                                                                                           |
|-------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **API Gateway / BFF**                           | Единая точка входа. TLS-терминация, троттлинг, скрытие внутренних сервисов, единая точка применения политик. Реализует требование «API-контракты скрывают конфиденциальные категории данных». |
| **IAM / IdP (RBAC + ABAC)**                     | Централизованные аутентификация и авторизация, MFA. Доступ к данным - по ролям и атрибутам (владелец записи, домен). Предотвращает «горизонтальный» доступ: пациент видит только свои данные. |
| **Consent Management**                          | Управление согласиями субъекта ПДн, реализация 152-ФЗ: прекращение обработки и удаление по запросу.                                                                     |
| **Каталог данных + тегирование (Data Lineage)** | Реестр данных, классификация и теги (`class/category/owner/retention`), прослеживаемость происхождения. Основа для tag-based policies.                                                     |
| **KMS / Vault**                                 | Централизованное управление ключами шифрования и секретами. Шифрование at rest для БД и объектного хранилища.                                                                              |
| **DLP + Audit / SIEM**                          | Аудит доступа к данным, обнаружение и алертинг нетипичных действий, контроль утечек. Проверка релизов на работу с тегированными данными.                                                   |

Эти блоки встроены в периметр целевой системы так, что любой продуктовый
сервис (портал, CRM, EMR, платёжный шлюз) взаимодействует с данными
исключительно через них - конфиденциальность обеспечивается «по умолчанию».

## 3. Продуктовые системы MVP

- **Портал клиента** - личный кабинет, самостоятельная запись к специалисту.
- **Портал ресепшена** - просмотр записей, напоминания пациенту и специалисту за день.
- **Сервис записи (booking)** - слоты и приёмы.
- **Медицинский домен (EMR)** - медкарты и заключения (спец. категория ПДн, усиленная защита).
- **CRM** - данные о клиентах.
- **Платёжный шлюз** - процессинг оплат, интеграция с 1С.
- **Интеграция с лабораторией** - обмен по API (закрытые контракты, доступ только к своим данным).

Категории данных пациента разнесены по доменам (booking, EMR, CRM, payment),
для каждого домена определены роли (RBAC) и атрибуты (ABAC) доступа.

## 4. Аналитический слой с учётом Privacy by Design

Отдельная **Data Platform**, изолированная от продуктивных данных:

1. **Ingestion + De-identification** - загрузка данных из OLTP/файлов с обязательным обезличиванием/псевдонимизацией ПДн на входе.
2. **Data Lake / DWH** - данные помечены тегами конфиденциальности; конфиденциальные поля хранятся обезличенными или в защищённом слое с ограниченным доступом.
3. **BI / ML / AI** - построение отчётов (P&L, ABC), обучение моделей на обезличенных данных.

## 5. Соответствие НФТ

- **Безопасность** - шифрование, RBAC/ABAC, аудит, согласия и удаление.
- **Масштабируемость** - сервисная декомпозиция, stateless-сервисы за API Gateway, горизонтальное масштабирование хранилищ.
- **Сопровождаемость** - чёткие доменные границы, единые точки политик.
- **Конфигурируемость** - политики доступа и теги задаются конфигурацией (IAM, каталог данных) без доработки кода.
