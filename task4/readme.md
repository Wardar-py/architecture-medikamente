# Оценка узких мест при миграции

## 1. Анализ ситуации

«Медикаменте» мигрирует с монолитных, файловых и ручных систем (1С в файловом режиме, Excel/сканы на общем диске, один физ. сервер) на современную
микросервисную архитектуру. Цель миграции - поддержать 5-кратный рост данных и команды, усилить безопасность ПДн, автоматизировать процессы.

### Ключевые процессы и компоненты, затрагиваемые миграцией
- **Базы данных**: переход от Excel/файлов 1С к PostgreSQL/S3, нормализация и перенос данных.
- **Коммуникационные каналы**: замена OLE/TCP и обмена файлами на API/очереди сообщений.
- **Серверное оборудование**: уход от единственного сервера к отказоустойчивой платформе (k8s/кластер).
- **Бизнес-логика**: декомпозиция монолитов на домены (booking, EMR, payment, CRM).
- **Безопасность данных**: внедрение шифрования, RBAC/ABAC, аудита, тегирования.

## 2. Диаграмма Исикавы: категории и причины узких мест

**Эффект (голова):** узкие места и снижение производительности после миграции.

| Категория                   | Возможные причины узких мест                                                                                                |
|-----------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| **Инфраструктура**          | Один физ. сервер (SPOF); нет резервирования и off-site backup; нехватка мощностей под 5x рост; оркестрация не внедрена      |
| **Программное обеспечение** | Монолиты 1С в файловом режиме; жёсткая связанность; нет автотестов и CI/CD; технический долг                                |
| **Интеграция**              | OLE/TCP без API и контрактов; обмен Excel/сканами; нет API Gateway и версионирования; синхронные вызовы без очередей        |
| **Персонал**                | Малая IT-команда (3 чел.); нет опыта микросервисов; сопротивление изменениям; bus factor (зависимость от 1 админа)          |
| **Процессы**                | Ручные операции; двойной учёт (Excel, 1С); нет процедур релизов/отката; нет мониторинга и алертинга                         |
| **Данные и безопасность**   | Нет классификации/тегирования; данные не нормализованы, дубли; риск утечки ПДн при миграции; сложность синхронизации данных |

## 3. Рекомендации по устранению узких мест

| № | Мера                                                                                 | Категория           | Приоритет |
|---|--------------------------------------------------------------------------------------|---------------------|-----------|
| 1 | Развернуть отказоустойчивую платформу (k8s-кластер, резервирование, off-site backup) | Инфраструктура      | Высокий   |
| 2 | Ввести API Gateway, контракты и асинхронный обмен (брокер сообщений Kafka/RabbitMQ)  | Интеграция          | Высокий   |
| 3 | Внедрить классификацию/тегирование данных и план переноса с нормализацией            | Данные/безопасность | Высокий   |
| 4 | Настроить CI/CD, автотесты, security-гейты                                           | ПО                  | Высокий   |
| 5 | Внедрить мониторинг и алертинг (Victoria Metrics/Grafana, SIEM)                      | Процессы            | Высокий   |
| 6 | Обеспечить синхронизацию данных при parallel run (CDC, сверка)                       | Данные              | Высокий   |
| 7 | Нанять/обучить команду, документировать (снизить bus factor)                         | Персонал            | Средний   |
| 8 | Поэтапная декомпозиция монолита (branch by abstraction)                              | ПО                  | Средний   |
| 9 | Формализовать процедуры релизов и отката                                             | Процессы            | Средний   |
| 10 | Нагрузочное тестирование под 5x профиль                                              | Инфраструктура      | Средний   |

Приоритет определён по влиянию на доступность/безопасность и риску блокировки миграции. Меры 1–6 критичны для запуска, 7–10 - для устойчивого развития.

## 4. Вывод

Основные риски снижения производительности сосредоточены в инфраструктуре, интеграции и данных.
Устранение высокоприоритетных причин до и во время миграции минимизирует деградацию и обеспечивает целевые масштабируемость, безопасность, доступность.
